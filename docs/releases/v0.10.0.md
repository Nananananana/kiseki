# KISEKI v0.10.0

More than photographs: the boundary. v0.10 is the version that made
room. Nothing in it changes what the library says about a photo
library -- and everything in it is what has to be true before a second
kind of evidence can arrive without breaking the first.

## Highlights

- **Every source may be absent** (ADR-0063). Not a courtesy to be
  remembered: a matrix seeds a library with every kind of evidence,
  removes one kind, and runs eighteen commands against what is left,
  seven times over. A derivation that comes to require a source fails
  the build.
- **Moments are compared in one shape** (ADR-0064). The matrix found
  this on its first run, and it was serious: every history feature --
  suggest, trend, lifecycle, insights, discover, compare, export --
  fell over on a library whose timestamps carried time zone offsets,
  which any producer might write and this one happened not to. The
  mixture met not in the derivations but in the value objects, where
  six types check that one moment precedes another. One shared helper
  now compares them, converting rather than truncating, while stored
  text keeps its offset so the API and the view still say what the
  camera said.
- **An answer names the kinds of witness it read.** `insights`,
  `discover` and `suggest` end with a line saying where their evidence
  came from -- and say nothing when there is none, because an answer
  with no evidence already says so in its own words.
- **A day of moving is a witness of its own** (ADR-0065). The first
  source after photographs: a count of steps per calendar day, with no
  positions, no times and no route. It landed early on purpose --
  designing a shared contract from one example would be designing it
  from imagination. Schema 6 gives it a table of its own; if it turns
  out to be a mistake, the table is dropped and nothing else notices.
- **A second input contract.** ActivityRecord v1 stands beside
  PhotoRecord v1, which is unchanged, and the two documents are not
  even the same shape at the top level. `kiseki activity` reads one;
  the same day given twice replaces rather than doubles.
- **The rules every contract shares** (`docs/records.md`). Name the
  owner and the producer, ignore unknown fields, speak the owner's
  local time, survive a byte order mark, land in a table of your own,
  be optional, and say what you will not carry. The ten questions a
  new source answers before it lands are in the same file, because a
  checklist nobody can find is not a gate.

## What the data said

- A byte order mark broke both record readers. PowerShell writes one
  without being asked, and the first ActivityRecord document written
  by hand refused to load. A contract meant for producers in any
  language has to accept a file with or without one -- and the fault
  was invisible while the only producer was our own.
- The time zone defect had been latent since v0.4. It was found the
  day the matrix existed, not the day it was written.

## Upgrading

- Schema 6: a v0.9 database migrates on connect. The new table is
  empty and nothing else changes.
- New command: `activity`. New contract: `docs/activity-record.md`.
- No behaviour changes for a library of photographs alone.

## Deferred, on purpose

The converter that turns an Apple Health export into an
ActivityRecord document waits for an export to exist. The receiving
half is done and tested; a converter written against an imagined XML
would be a guess, and this project has a rule about those.

# Proposal 0002: The v0.4 plan



Status: accepted. Continues proposal 0001; the order below is the
build order.

## In order

1. **Single-photo context (FR-507).** Roughly a third of the library
   is photographs that form no stop -- complete statements of
   interest, unused since v0.1. They ride the per-image reading path
   v0.3 built (resumable, limit-capped; about 1,200 images), and
   their subjects annotate the nearest stop or anchor: what someone
   keeps photographing at a place they keep returning to. This work
   rebuilds representative thumbnail selection, and brings withheld
   photographs (`use_for_preference: false`) out of caption
   selection, closing the deferral in ADR-0032.
2. **Hybrid search.** The v0.4 core and the Phase 2 foundation:
   FTS5 keyword + bge-m3 semantic + time and entity filters over
   captions, topics and evidence; `kiseki ask` and `/ask`; every
   answer cites the facts it rests on. Survey answers 5-9 of
   proposal 0001 are the implementation sketch.
3. **Temporal questions.** Filters over the kept profile history and
   evidence dates: recent, rising, in a named year. No new storage.
4. **Place entities.** Coordinates read as named places through an
   offline gazetteer shipped or fetched once. No lookup at question
   time; "no network required" includes questions.
5. **Place narration.** The owner's dynamic-label idea, shaped to
   ADR-0012: a place's measures become a closed fact list and a
   local model words them with citations ("your favourite dining
   area" as an interpretation, never a stored category).
6. **Lifecycle labels.** Derived at read time from the trend
   history (dormant = faded across consecutive readings). Stored
   nowhere.

Two small pieces ride along where convenient:

- **`kiseki doctor`** -- one deterministic screen of library health:
  schema version, refused captions and screen readings, missing
  thumbnails, unread screenshots, consent counts. The runbook's
  "evaluate" step, mechanised. No model.
- **Evidence-kind display** -- the view and the API say whether an
  interest rests on photographs, screenshots or visits. Every
  interpretation can already name its evidence; this makes the kind
  visible.

## A preview of v0.5 (Phase 2)

- **`kiseki suggest`** -- the day-trip question, answered in the
  shape of ADR-0022: a closed fact list (interests, outings, place
  entities, the trend) and a cited answer. Candidates come from the
  owner's own history first -- returned-to places, unexplored
  directions -- before any external source is even considered;
  external candidate providers would be ports.
- **Interest export** -- the first code for "personal data and
  shared interests are fully separated": an explicit command that
  writes a shareable pack of themes and scores only. No evidence
  references, no coordinates finer than the blur grid, nothing that
  was not derived. Preparation for the Phase 3 community.
